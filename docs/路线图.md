## 一、已经做完的

### 1.1 框架本体

把每次运行固化成「录制带」（每个 LLM / 工具调用接缝的输入输出 + 不可变指纹），
支持三种回放模式：**精确重放**（逐字重演）/** 断带保护**（录制带不完整时拒绝即兴编造）/
**钻取式反事实**（从第 N 步换成另一条岔路）。

判定侧用「决策签名」把模型自由文本压成可比较指纹，再做**序列对齐** ——
不是按序号对齐。差异分五档（D0~D4），"允许多大差异"写成 JSON 配置，由 CI 退出码结算。

**189 项单测，零第三方依赖。**

### 1.2 真实模型接入

接入阿里云百炼的 `qwen-plus-latest` / `qwen-turbo`（原生 function calling），
跑了 **7 次录制、8 组对照实验**。最有价值的结论是一条**没有发现问题的发现**：

> 温度 0 跑 3 次 + 温度 1.0 跑 3 次，**六条轨迹的 steps 哈希完全相同**。
> 分叉的来源不是采样温度，而是**任务有没有选择空间** ——
> 一个没有选择空间的任务，测不出稳定性。

同时暴露并修掉了两处**判据误报**（只差小数位数被判成"结论被替换"、
drill 的分叉被误报成上游不稳定）。两处都不报错，只是安静地给出错结论 ——
**框架的 bug 会报错，判据的 bug 不会。**

详细过程、逐条判定、三组门禁结算见 [`真实实验记录.md`](真实实验记录.md)。

## 二、接下来可以加的

按「价值 / 工作量」排序：

| 想法 | 价值 | 工作量 | 备注 |
|---|---|---|---|
| **GitHub Actions workflow** | 中 | 极小 | 把 README 里那段 CI 变成真能跑的 `.github/workflows/gate.yml`。那段已逐条实跑验证过，可直接落盘；基线带用的是入库的真实模型轨迹，**CI 里不需要 API Key、不需要联网** |
| **多工具并行调用** | 中 | 小 | 模型一次返回多个 `tool_calls` 时，目前只执行第一个，但会把总数记进 `meta` —— 不让它无声无息过去 |
| **异步 / 多进程下的 `parent_seq` 因果还原** | 中 | 大 | 目前是已知局限里的第一条。异步区间内"谁真正导致了谁"只预留了字段，没有实现 |
| **内容寻址去重** | 低 | 中 | 同一个 prompt 的多次请求现在各存一份。哈希已经算好了，属于"预留了没做" |
| **把 `intent` 级接进分级主链路** | 低 | 小 | 目前 `intent` 是可用的第三种分辨率，但没有参与五档判定 |

## 三、相关项目

同一份领域数据（UCI Online Retail 清洗后 392,692 行零售交易）上，
同作者还做了另外两件事，三者分工是：

```
evalguard    答得对不对              （质量）
faultprobe   坏了会怎样              （鲁棒性）
replayprobe  改动之后走的还是同一条路吗  （行为回归）
```

- **faultprobe** —— 给 Agent 注入 12 类故障（工具超时、返回畸形、上游 5xx、
  缓存击穿……），量"坏了会怎样"。它与本项目互补：一个测**外部变坏**时的行为，
  一个测**内部改动**后的行为。
- **evalguard** —— 量"答得对不对"，属于评测集范式的质量门禁。

三者共用同一份 `retail_truth.db`，所以三张成绩单可以并排看。
